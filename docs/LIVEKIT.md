# Видеосвязь урока (A8) — self-hosted LiveKit

Камера, микрофон и демонстрация экрана в комнате урока работают на собственном
LiveKit SFU на той же ВМ. Внешних сервисов и платных подписок нет.

## Как устроено

```
браузер ──wss://allvision-pulse.ru/livekit──► хостовый nginx (SSL) ──► 127.0.0.1:7880  (сигналинг)
       └─WebRTC-медиа──────────────────────► 158.160.209.107 UDP 50000-50200 / TCP 7881
```

- **Сигналинг** идёт через уже существующий SSL-слой: браузер не увидит смешанного
  контента, отдельный сертификат не нужен.
- **Медиа** идёт напрямую на публичный IP, минуя nginx — так и должно быть у WebRTC.
  Контейнер поэтому в `network_mode: host`: проброс UDP-диапазона через docker-proxy
  и NAT внутри бриджа ломает согласование ICE.
- **TCP 7881** — фолбэк для сетей, где UDP зарезан (школы, офисы). Отдельный TURN
  не поднимали: он закрывает те же сценарии, но требует своего сертификата на 443,
  который занят nginx.

## Ключи и токены

`shared/.env` на ВМ:

```
LIVEKIT_KEYS=APIacademy: <секрет>
LIVEKIT_URL=wss://allvision-pulse.ru/livekit
```

`LIVEKIT_KEYS` — родной формат LiveKit (`ключ: секрет`), его читают и сервер, и наш API,
чтобы не расходились. Секрет в репозиторий не коммитится.

Клиент никогда не видит ключей: `GET /api/academy/lessons/:id/video-token` проверяет,
что запрашивающий — преподаватель этого урока, родитель ребёнка или админ, и выдаёт
короткоживущий (4 часа) JWT на комнату `lesson-<lessonId>`. Комната создаётся при первом
входе и живёт 5 минут после ухода последнего участника, чтобы перезаход на плохой связи
не терял сессию.

Если `LIVEKIT_URL` не задан, эндпоинт отдаёт `{ enabled: false }`, и комната урока
работает без видео — сцены, рисование и чат идут по нашему WebSocket. Это осознанная
мягкая деградация: падение SFU не должно срывать занятие.

## Эксплуатация

```bash
docker logs allvision-studio-livekit --tail 50
docker compose -f infra/prod/docker-compose.prod.yml up -d --force-recreate livekit
```

Проверка сигналинга: `curl -s -o /dev/null -w "%{http_code}" https://allvision-pulse.ru/livekit/` → `200`.

Маршрут `/livekit/` живёт в хостовом nginx (`/etc/nginx/conf.d/allvision-pulse.conf`,
вне репозитория; резервная копия рядом с суффиксом `.bak-livekit`).

## Известные ограничения

- `node_ip` в `infra/prod/livekit.yaml` прописан статически. **При смене публичного IP
  ВМ его нужно обновить**, иначе медиа перестанет соединяться при живом сигналинге.
  Автоопределение через STUN отключено намеренно: оно подмешивало в ICE-кандидаты
  docker-мосты (172.17/172.19), нерутабельные для внешнего клиента.
- Порт 7880 доступен снаружи по plain HTTP. Подключиться без валидного токена нельзя,
  но наш клиент всегда ходит через `wss` — при желании порт можно закрыть на уровне
  облачной группы безопасности, оставив 7881 и UDP-диапазон.
- Записи урока нет: LiveKit Egress не разворачивался (нужен отдельный контейнер и место
  под файлы). Комната рассчитана максимум на 8 участников.
- ВМ 4 ГБ RAM: SFU держит поток, не перекодирует, поэтому нагрузка невелика, но
  собирать docker-образы параллельно с идущим уроком не стоит.
